Key Concepts

The seven ideas that matter most for understanding what a web browser is and how it works.

1. Client–Server Model

The web works as a client–server system. The browser is the client (it requests a page) and the web server is the provider (it delivers the page). When you type a URL, the browser asks a server for a resource and the server sends it back.

2. HTTP (HyperText Transfer Protocol)

HTTP is the protocol the browser uses to ask a server for a page and to receive the answer. A request goes out (for example, GET /page.html) and a response comes back with a status code such as 200 OK, plus the page content.

3. DNS (Domain Name System)

DNS turns a friendly name, like example.com, into the numeric IP address of the server that holds the page. It is how a browser finds the right machine to talk to before it sends any request.

4. DOM (Document Object Model)

When a browser reads HTML, it builds a tree called the DOM, where every element and piece of text is a node. This tree is the in-memory representation of the page that the browser works with.

5. CSSOM (CSS Object Model)

The CSSOM is the tree the browser builds from the page's CSS — the style rules that describe how things should look. The DOM and the CSSOM are combined into a render tree before anything is drawn.

6. Rendering Engine

The rendering engine is the heart of a browser. It reads the HTML and CSS, builds the DOM and CSSOM, and turns them into the page you see through the pipeline: parse → render tree → layout → paint → composite. The main engines today are Blink, Gecko and WebKit.

7. Sandbox (Security)

A sandbox keeps untrusted web content contained. Each tab runs in its own separate process, so if one page is buggy or exploited it cannot easily damage the rest of the browser or the computer. HTTPS, memory safety and process isolation all work together to keep the user safe.
